# Build notes, Rev A

What has to survive a long run. One lesson per entry, newest at the bottom.

1. **analog.com datasheets** do not load through curl or WebFetch. In the built-in browser they do, and pdf.js from cdnjs can be imported in the page to pull text per page (`import('https://cdnjs.cloudflare.com/ajax/libs/pdf.js/4.0.379/pdf.min.mjs')`, then `getDocument({data})`).
2. **JLC part pages:** WebFetch on `jlcpcb.com/partdetail/C<nr>` gives the PCBA Type but no stock. The same page in the built-in browser shows "In Stock" in its text after about 2 s.
3. **jlcsearch.tscircuit.com** misses many parts (TMC5240, most JST originals) and its database overloads under bursts. Pace requests and never read "no result" as "does not exist".
4. **Schematic generation:** every pin gets a global label, so a net is its name. `circuit.py` reads the netlist back through kicad-cli after writing and refuses to pass if KiCad reads a different one.
5. **UUIDs are uuid5 of sheet and reference**, so regenerating the schematic keeps the board's links.
6. **The ESP32-C6-MINI-1U antenna connector is a third-generation part** (W.FL, MHF III, AMMC), not U.FL (datasheet v1.5 p42). The pigtail must match.
7. **TMC5240 SLEEPN may not exceed VS + 0.3 V** (p10), so it is tied to VM, not to 3.3 V, which is alive on USB power when VM is not.
8. **Area count before layout:** all features on 85 x 65 mm, top side only, came to about 76 % courtyard fill. The RJ45 jack went first (CTL-03 order). Count area per region before choosing connectors next time.
9. **The motor side of the TMC5240 TQFN is one edge** (pins 17 to 24). OUT1B and OUT2B come out in the opposite order to OUT1A and OUT2A, so a planar route to a 4-pin connector needs the order A1 A2 B2 B1.
10. **Freerouting runs headless only** (`-Djava.awt.headless=true ... --gui.enabled=false`). With the GUI it throws exceptions in its paint thread and once wrote an empty session file. It stops improving after about 13 passes on this board (2 minutes each); `-mp 14` is enough.
11. **Freerouting's own "unrouted" count is not KiCad's.** It reported 250 to 340 open where KiCad's DRC, after import, found 45 to 55. Only the DRC count after `board.py ses` means anything.
12. **Freerouting does not tie supply pads to inner planes once the top layer is full**, and it does not finish the drivers' SPI pins. `tools/complete.py fanout` lays these on the placed board before routing, and the DSN export marks them `(type protect)`.
13. **KiCad writes an inner layer set to "power" as `(type power)` in the DSN**, and Freerouting then leaves it alone. `board.py dsn` sets inner layer 1 to power and inner layer 2 to signal on purpose. Check the printed layer types after every export: a failed assert there once left an unpatched DSN behind that the router then used.
14. **A shell pipeline hides a failed step.** `board.py place | tail` returns tail's status; a failed placement then let the next step run on the old board. Write the log to a file and test it.
15. **Tracks on inner layer 2 cut pieces off the +3V3 plane.** A via on such a piece reaches nothing. After routing, `complete.py` tests against the largest filled piece (`filled_plane`), not the plane's outline.

## Paused on 2026-11-10 (second time), at the owner's request

**The board is not routed.** Nothing may be ordered. Specs, schematic (ERC 0), `check_netlist.py` (0 mismatches), calculations, fit check (0 failures), placement and the tools are done and committed. Not done: routing to DRC zero, copper and silkscreen inspection, production files, blind review, STATE/BACKLOG/README, the PR.

Where routing stands:
- `ptz-driver.kicad_pcb` in the worktree is the **placed board with the pre-routes of `complete.py fanout`**, not a routed board. It is regenerated by `board.py place` then `complete.py fanout`.
- Best routed result so far: `route/rev-a.ses` on `route/rev-a_input.kicad_pcb` (the run with inner layer 2 open). After `board.py ses`, `board.py finish` and three rounds of `complete.py` it had 39 unconnected items and no shorts or clearance errors. Both files are local only (the input board is tracked, the session file is ignored), and that input board was made before the escape vias below.
- What was still open in that result: the four drivers' chip selects (pin 26, fenced in between SLEEPN and the bus pins), several DIAG0/DIAG1 pins, some sensor and Ethernet signals, and about ten pieces of the +3V3 plane cut off by tracks on inner layer 2.

Last change, **not working yet**: `fanout` now gives fine-pitch signal pins an escape via (107 of them). The escape via of pin 26 lands where the SPI_SCK pin's track must pass, so SPI_SCK no longer reaches its bus line on any driver ("driver bus: 8 pins on 2 lines"). Two W5500 ground pins also lost their way out. Next step: give pin 26 its via further out or above the SLEEPN resistor, or route the bus pins first and pin 26 after; then check that the fanout board has 12 bus pins on 3 lines and a clean DRC before starting Freerouting.

1. `$KP tools/board.py place > place.log 2>&1` and check the log for "0 without a place".
2. `$KP tools/complete.py fanout`; expect no "not routed" and no "no way out". DRC on that board must show no violations other than silkscreen and loose escape vias.
3. `cp ptz-driver.kicad_pcb route/rev-a_input.kicad_pcb`, `$KP tools/board.py dsn route/rev-a.dsn`, check for one `(type power)` and three `(type signal)` layers and `(type protect)` wires.
4. In `route/`: `java -Djava.awt.headless=true -jar ~/.kicad-mcp/freerouting.jar -de rev-a.dsn -do rev-a.ses -mp 14 --gui.enabled=false`, about half an hour, as a tracked background job.
5. `cp route/rev-a_input.kicad_pcb ptz-driver.kicad_pcb`, `$KP tools/board.py ses route/rev-a.ses`, `$KP tools/board.py finish`, `$KP tools/complete.py 6`, then `$KP check_board.py`.
